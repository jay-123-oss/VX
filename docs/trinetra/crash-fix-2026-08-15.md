# Crash-fix report — camera permission and thermal lifecycle

## Diagnosis

The supplied log contains two separate lifecycle failures from the tested APK.

The first is:

```text
Unable to resume activity: SecurityException: Camera permission is not granted
at com.example.vx.ARCoreVisionManager.resume
at com.example.vx.MainActivity.onResume
```

The second is:

```text
Unable to pause activity: IllegalArgumentException: Listener was not added
at android.os.PowerManager.removeThermalStatusListener
at com.example.vx.ThermalDutyManager.stop
at com.example.vx.MainActivity.onPause
```

The stack-frame numbers in the log do not match the current repository sources: the log points to `MainActivity.onResume` around line 117 and `ARCoreVisionManager.resume` around line 24, while the current source places those methods substantially later and already has a permission guard. This indicates the reported crash was produced by an older APK, but the thermal listener bug also required a defensive source fix.

## Fixes in the current source

`ARCoreVisionManager.createIfNeeded()` checks `Manifest.permission.CAMERA` before constructing an ARCore `Session`. Session construction and resume remain wrapped in failure-safe handling. `MainActivity.onResume()` checks permission before starting the camera pipeline, and the startup boundary now catches a permission race or other runtime startup failure, stops partially started components, and shows a Hindi message instead of allowing the Activity to crash.

`ThermalDutyManager` now tracks whether the thermal listener was actually registered. `start()` is idempotent and `stop()` removes the listener only when registration succeeded. Both registration and removal are protected by failure-safe handling. Repeated pause/resume, permission denial, and partial startup can therefore not call `removeThermalStatusListener()` for a listener that was never added.

## Verification

The Android JVM test suite passes and the debug APK assembles successfully after these changes. A physical device is still required to verify Android permission revocation, repeated Activity pause/resume, ARCore support, and thermal callbacks.

## Required installation procedure

Uninstall the old `com.example.vx` package or clear its app data before testing this APK. Install the newly attached APK, launch it, deny camera permission, and confirm that the Hindi explanation appears without a crash. Re-open the app, grant permission, then background/foreground it several times. Finally revoke camera permission in Android Settings while the app is paused, relaunch it, and confirm that the app remains open with the permission message.

Do not judge the fix using an older APK or an APK whose checksum differs from the current artifact. The latest checksum is recorded in the task report.

## Safety limitation

This fixes the reported lifecycle crashes; it does not certify ARCore depth quality, pothole detection accuracy, or collision safety. Those require controlled physical-device testing with an observer.
